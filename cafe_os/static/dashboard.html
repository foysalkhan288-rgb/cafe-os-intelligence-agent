📖 Guide & Situations

    
What each section does, and what happens in different scenarios


    

      
🏠 Dashboard (Home)

      
Live overview of your cafe. Shows 4 stats: Menu Items, Low Stock count, KDS Tickets, Open Shifts. Below: Recent Orders (last 5) and Low Stock Alerts.

      
SituationWhat happens

        
No orders yet"No orders yet" shown in Recent Orders

        
All stock above threshold"All stocked up" in Low Stock Alerts

        
Some items below reorder levelListed with current stock and threshold

        
KDS tickets activeCount shown, click Kitchen tab to manage

      

    


    

      
🧾 Orders

      
Create orders with counter number, optional table, and items JSON. Each order triggers the LangGraph pipeline: customer lookup → parse → validate modifiers → calculate totals → dispatch KDS → deduct inventory.

      
Button / ActionWhat it does

        
Create OrderSubmits the form. On success: order created, KDS ticket dispatched, inventory deducted. Result shown below.

        
🎲 Create Demo OrderPicks a random demo order (latte, cappuccino, etc.) and creates it. Good for quick testing.

      

      
Possible situations:

      
SituationResult

        
Valid items (latte-001, etc.)Order created, total calculated, KDS dispatched, inventory deducted

        
Invalid menu item ID (e.g. "ashiqe-001")400 error: "Menu item not found" — order rolled back

        
Empty items array400 validation error — at least 1 item required

        
Modifier "oat-milk" in itemsOat milk ingredient deducted instead of regular milk, +$0.50 price delta

        
Special instructions "extra shot"Modifier keyword auto-extracted, extra espresso shot added, +$0.75

        
Customer with 150 points (cust-001)10% loyalty discount applied automatically

        
Customer with 50 points (cust-002)No discount (needs 100+ points)

        
No customer specifiedNo loyalty lookup, no discount

        
With table numberTable assigned to order

      

    


    

      
👨‍🍳 Kitchen (KDS)

      
Live kitchen display. Tickets appear in real-time via WebSocket. Each ticket shows items, quantities, modifiers, and special instructions. Click buttons to update status.

      
ButtonWhat it does

        
Ack (Acknowledge)Kitchen sees the order — status → "acknowledged"

        
StartCooking begins — status → "in_progress"

        
Done (Complete)Order ready — status → "completed" (hidden from default view)

      

      
Possible situations:

      
SituationResult

        
No active tickets"No active tickets" shown

        
New order createdTicket appears instantly via WebSocket (no refresh needed)

        
WebSocket disconnectedRed dot shown, auto-reconnects in 3s

        
Ticket completedRemoved from default view, still in DB

        
Multiple ticketsGrid layout, sorted by dispatch time

💰 Shifts

      
Manage cashier shifts. Open with cashier ID and opening cash. Reconcile by entering actual cash counted. Cash payments auto-bank to the open shift.

      
ButtonWhat it does

        
Open ShiftCreates new shift with opening cash as expected_cash

        
Reconcile & CloseCompares expected vs actual cash, closes shift, flags if difference > $10

      

      
Possible situations:

      
SituationResult

        
Actual = Expectedcash_difference = 0, not flagged

        
Actual differs by ≤ $10Flagged = false (within tolerance)

        
Actual differs by > $10Flagged = true (needs review)

        
Reconcile already-closed shift400 error: "already closed"

        
Reconcile nonexistent shift404 error: "not found"

        
Cash payment with 1 open shiftOrder total banked to that shift's expected_cash

        
Cash payment with 0 or 2+ open shiftsPayment succeeds but no banking (ambiguous)

        
Card/mobile paymentNo shift banking (only cash affects drawer)

      

    


    

      
📈 Reports

      
Analytics and reporting. Each button loads data into the result box below.

      
ButtonWhat it loads

        
Daily SalesGross/net revenue, tax, order count, avg basket, payment breakdown, top item

        
Sales ForecastRolling average prediction for N days ahead

        
Menu Engineering4-quadrant matrix: Stars, Puzzles, Plowhorses, Dogs (by margin & popularity)

        
Waste AnalyticsActual vs theoretical consumption, variance, high-variance items

        
Branch ComparisonPerformance across branches (revenue, orders, avg basket)

        
Record WasteLog spoilage/overproduction/expired with ingredient, qty, unit, reason

      

    


    

      
👤 Customers

      
CRM lookup by customer ID. Shows name, phone, reward points, preferences. Points accrue on payment (1 point per $1).

      
SituationResult

        
Existing customer (cust-001)Details shown, points updated after payments

        
Nonexistent customer404 error: "not found"

        
After paying an order for cust-001Reward points increase by order total (floor)

        
100+ points on order10% loyalty discount applied to order total

⚙️ Settings

      
Configure API base URL and API key. Stored in browser localStorage. API key is sent as X-API-Key header on all /api/v1 calls.

      
SituationResult

        
Auth enabled (API_KEY set on server)Must enter key here or all /api/v1 calls return 401

        
Auth disabled (no API_KEY)Leave empty — all calls work without key

        
Wrong key entered401/403 on all data calls

      

    


    

      
🔌 Authentication

      
Controlled by API_KEY environment variable on the server.

      
API_KEY stateBehavior

        
Set (non-empty)All /api/v1/* and /ws/kds require X-API-Key header or ?api_key= param

        
Unset (empty)Open access — no authentication needed

        
Wrong key401 for HTTP, 403 (close) for WebSocket

      

      
Public endpoints (no auth): /, /docs, /redoc, /openapi.json, /healthz, /dashboard
